Development

Development turns specifications into shipped software, with the receipts to prove it.

Takeaways

  1. OneDevelopment is where a specification stops being a claim. Nothing counts as shipped without tests, metrics and docs behind it.
  2. TwoIt runs as a pipeline, and each stage has to close before the next opens.
  3. ThreeWhat ships becomes Product’s evidence. Observe measures it against what the brief promised.

The pipeline

  1. Intake and planTake the specification, confirm it can be built as written, and sequence the work.
  2. Build and reviewWrite it, test it, and have it read by someone who did not write it.
  3. ShipDeploy it, watch it, and hand the outcome data back to Product.

The input is a buildable specification from Design. The output is software in production together with the evidence that it works — which is what lets Product close the loop rather than assume it.
